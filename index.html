Three phases, one tutorial

No hand-written CSS selectors. One discovery subagent explores the live site, hardening subagents pick robust locators, then the orchestrator checkpoints the spec step by step and renders the PDF.

1

🕹️ Explore

A single discovery subagent walks your task on the live site via the MCP server, recording each step and its candidate identifiers from the accessibility tree — never guessing selectors.

2

🔒 Harden & checkpoint

Read-only subagents pick the most robust locator per element — getByRole > getByLabel > getByTestId > getByText > CSS. The orchestrator appends one step at a time and saves after each.

3

🖍️ Render

The renderer parses the spec, replays it in Chromium, screenshots each step, draws a red circle around the target, adds a caption banner, and compiles the PDF next to the spec.

Tutorials live as docs.

The deliverable isn't a brittle screen recording — it's a replayable spec file. Because it's real code, you can commit it, review it in pull requests, and re-run it whenever the site changes. Each step is saved the moment it's written and marked [draft] until it resolves on the live site, then [verified], so a run can stop and resume without losing progress. And since the spec replays against the live page, a quick --verify run flags exactly which steps have drifted — so you know the moment a tutorial goes stale.

✓ Committable ✓ Resumable checkpoints ✓ Drift-checkable 
// Tutorial: How to search on Wikipedia
// PDF output: wikipedia-search.pdf
import { test } from '@playwright/test';

test.use({ viewport: { width: 1280, height: 800 } });

test('How to search on Wikipedia', async ({ page }) => {
  // First goto is the start URL, not a step
  await page.goto('https://www.wikipedia.org');

  // Step 1: Click the search box [verified]
  await page.getByRole('searchbox', { name: 'Search Wikipedia' }).first().click();

  // Step 2: Type your query [no-highlight]
  await page.getByRole('searchbox', { name: 'Search Wikipedia' }).first().fill('Playwright');
});

Re-run it: npx playwright test wikipedia-search.spec.ts

Install in one line

It's an Agent Skills package — a folder with a SKILL.md that works in Claude Code, Cursor, and VS Code Copilot.

1 · Copy the skill in

# macOS / Linux  →  ~/.claude/skills
curl -fsSL https://raw.githubusercontent.com/fizy069/pathfinder/main/install-remote.sh | bash -s -- claude --deps --mcp

# Windows (PowerShell)
irm https://raw.githubusercontent.com/fizy069/pathfinder/main/install-remote.ps1 -OutFile install.ps1
.\install.ps1 claude -Deps -Mcp; rm install.ps1
Installs to ~/.claude/skills/pathfinder — this folder is read by Claude Code and Cursor.
# macOS / Linux  →  ~/.cursor/skills
curl -fsSL https://raw.githubusercontent.com/fizy069/pathfinder/main/install-remote.sh | bash -s -- cursor --deps --mcp

# Windows (PowerShell)
irm https://raw.githubusercontent.com/fizy069/pathfinder/main/install-remote.ps1 -OutFile install.ps1
.\install.ps1 cursor -Deps -Mcp; rm install.ps1
Installs to ~/.cursor/skills/pathfinder. You can also import from GitHub via Settings → Rules → Add Rule → Remote Rule.
Windows blocking scripts? Run powershell -ExecutionPolicy Bypass -c "irm https://raw.githubusercontent.com/fizy069/pathfinder/main/install-remote.ps1 -OutFile install.ps1; .\install.ps1 claude -Deps -Mcp; rm install.ps1"

2 · The browser-automation MCP server

The --mcp / -Mcp flag wires this up for you. To do it by hand:

claude mcp add playwright \
  -- npx @playwright/mcp@latest
# add to ~/.cursor/mcp.json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}
The skill drives a real browser through this server. Without it, it can't explore the live site.

3 · Install the browser, then just ask

Skipped if you passed --deps/-Deps — otherwise, once inside the installed skill folder:

npm install
npx playwright install chromium

Then tell your agent: "generate a tutorial for how to search on Wikipedia." It writes tutorials/<slug>.spec.ts checkpoint-by-checkpoint, then renders the PDF right next to it.
